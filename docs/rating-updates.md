# Penumbra rating-update contract

`src.hybrid.rating_updates.update_rating` returns a new request-history frame for `operation="add"`, `"edit"`, or `"remove"`. It does not persist, authorize, train, refresh the bundle or mutate caller inputs. Add requires a new user/movie pair, finite 0–5 rating and nonnegative integer timestamp. Edit requires an existing unique pair and a rating; timestamp is preserved unless explicitly supplied. Remove requires an existing unique pair and accepts neither rating nor timestamp. Ambiguous duplicate events are rejected pending an upstream event-ID contract. Existing integer indexes are retained to avoid invalidating unrelated users through row renumbering. Generic-index insertion may change index dtype and cause conservative extra cache misses, never intentional score changes.

| Signal | Request history change | Frozen dependencies | Refresh boundary |
|---|---|---|---|
| Collaborative | Same candidate/user MF prediction does not learn from add/edit/remove | Profile-only MF factors, biases, counts and global mean | No public fold-in/partial_fit/update exists; teammate-owned new artifact/interface required |
| Personal | Recomputes genre preferences and recency using current history | Frozen catalog and population quality evidence | Safe request-time recomputation; no learned-ranker refit |
| Content | Rebuilds user profile and history-only text representation | Frozen selected configuration and catalog | Supported request-time profile/vectorizer construction, not ranker/MF training |
| Quality | Unchanged for a fixed candidate/user | Bundled reference ratings, excluding target user | New versioned population artifact required |
| Popularity | Unchanged for a fixed candidate/user | Bundled reference counts, excluding target user | New versioned population artifact required |

The fixed scaler and logistic coefficients do not change. A new feature vector may change the final individual decision score. Watched eligibility immediately excludes additions and makes removals eligible if no remaining history record watches that movie. Group eligibility is the union of member watches: a changed pool can change every member's percentile ranks even when their individual histories are unchanged. Rating-only edits with an unchanged pool miss the changed member's cache and can hit other member entries. Nonmembers' independent recommendations do not change because caller histories do not replace the bundle's population snapshot.

An unseen positive user ID gets the MF snapshot's existing item-bias/global fallback, not newly learned user factors. Adding the first rating updates Personal/Content while MF remains cold for that ID. Removing all supplied ratings from a previously fitted user does not erase its stored MF representation. Cache invalidation is not model updating or data erasure. Old derived score entries are bounded and become unreachable for changed histories until eviction/clear; an erasure policy must also address cache clearing and model artifacts.

Request-time work: validate event/history, apply pure update, persist/version outside this module, serve the returned snapshot; fingerprints prevent sequential stale reuse. Frozen model work: no fit, weight changes, or population edits. Future scheduled refresh: Collaborative owner must specify legitimate fold-in or artifact-refresh semantics, user/movie mapping, confidence/cold fallback, provenance and deletion behavior; Hybrid must validate feature compatibility, compare on validation, atomically swap an immutable versioned bundle and invalidate relevant worker caches. No such schedule or new model is implemented in Week 8. Do not silently substitute another saved MF artifact.

Concurrent caller edits of a frame/bundle being scored are unsupported. Production persistence needs transactions, authorization, event IDs, idempotency/version checks and immutable request snapshots. These are deployment handoffs, not hidden behavior of this Python helper.
